# 胜算云支付/充值能力接入分析

> 版本 v0.1 · 2026-09-17 · 状态：分析稿（未实施）
>
> 结论先行：**当前上游没有开放任何支付 API**（参考源仅有 `/user/info` 的余额读取），
> 因此接入必须分阶段：P0 用"外跳充值页"零后端依赖落地；原生支付体验（站内充值、
> 扫码、余额联动）全部依赖胜算云后端新增接口，接口清单见 §4。

## 1. 现状盘点

| 能力 | 现状 | 来源 |
|---|---|---|
| 余额读取 | ✅ 已实现（`/user/info`，jwt_token，Assets/10000=元） | SSY-Switch |
| 余额展示/手动刷新 | ✅ 账号卡片 | SSY-Switch |
| 充值入口 | ❌ 未实现（计划中的"充值按钮"还没做） | 实施计划 WP5 |
| 余额不足提示（402） | ❌ 错误诊断映射未实现 | 实施计划 WP5 |
| 上游支付/订单 API | ❌ 不存在 | 参考源核实 |
| 上游充值 Web 页 | 推测存在于 www.shengsuanyun.com（登录后），URL 待产品确认 | 未验证 |

关键事实：**充值必须发生在胜算云的 Web/后端**（微信/支付宝商户资质、合规、
发票、退款都在胜算云侧）。客户端无论怎么做，角色都只能是"引导 + 状态联动"，
不能也不应自己碰资金流。

## 2. 三阶段方案

### P0：外跳充值（无后端依赖，1-2 天）

用户点"充值"→ 系统浏览器打开胜算云充值页 → 支付完成回到应用 → 手动/自动刷新余额。

```
[账号卡片 充值按钮]
   → opener.open_url("https://www.shengsuanyun.com/<充值页>?from=ssy_switch")
   → 应用失焦监听/定时器：窗口重新聚焦后自动 refresh_balance
   → 余额变化 → 卡片金额更新（可选 toast "充值到账 ¥xx"）
```

细节：
- URL 与归因参数（`from`）需产品确认；**不得**在 URL 里带 api_key/jwt_token/uid
  （会进浏览器历史和访问日志）
- 充值页需要用户在 Web 重新登录——这是 P0 的体验断点，P1 解决
- 同步把 402（余额不足）错误码映射到"前往充值"按钮（实施计划 WP5 本来就要求）

验收：点按钮能到充值页；支付后回应用余额自动更新；402 报错有充值引导。

### P1：免登录外跳 + 余额联动（需后端 2 个接口）

解决"充值还要再登录一次"和"不知道支付成没成功"：

1. **一次性登录票据**：后端提供 `POST /auth/ticket`（x-token 认证）→ 返回
   一次性 ticket；客户端拼 `充值页?ticket=xxx`，Web 用 ticket 换会话后跳充值页。
   ticket 单次有效、5 分钟过期——比在 URL 里带 token 安全得多。
2. **订单/到账查询**：要么 `GET /wallet/transactions?since=`（流水），
   要么 Web 支付成功后 302 到 `ssyswitch://recharge-success?amount=<脱敏>`
   （只带金额、不带卡号/订单号敏感字段），客户端收到深链自动刷余额。

体验：点充值 → 浏览器已登录态直达支付 → 支付完自动回应用并看到新余额。

### P2：站内原生充值（需后端完整订单 API + 商户能力）

客户端内完成支付，不离开应用：

```
[充值面板] 选金额/套餐
  → POST /wallet/orders (x-token) → { order_id, pay_url, qr_url, expire_at }
  → 客户端展示支付二维码（微信/支付宝）
  → GET /wallet/orders/{id} 轮询（2s，指数退避，上限 5 分钟）
  → paid → 关闭面板 + 余额刷新 + 成功动效
```

- 技术上客户端只需展示二维码图片 + 轮询，**不需要**引入微信/支付宝 SDK
  （拉起收银台那套是给商户 App 的，我们不是资金主体）
- 需要：订单创建/查询接口、二维码图片或内容字符串、有效期与超时语义、
  优惠券/体验金/套餐规则的展示数据
- 合规注意：金额展示、退款引导、发票入口都跳 Web；客户端不做任何资金操作

## 3. 客户端改动清单（按阶段）

| 阶段 | 改动 | 位置 |
|---|---|---|
| P0 | 充值按钮 + 归因外跳 + 聚焦后刷余额 | `ShengsuanyunAuthSection`（账号卡片）|
| P0 | 402 → "余额不足，前往充值"错误映射 | Provider 错误提示层 |
| P1 | ticket 换取 + 拼接 | `shengsuanyun/client.rs` |
| P1 | `recharge-success` 深链 + 自动刷余额 | `lib.rs` 深链白名单 + 前端 |
| P2 | 充值面板 UI（金额选择、二维码、轮询） | 新组件 + 2 个 command |
| 全程 | 漏斗埋点：按钮点击→充值页→支付成功→余额变化 | 匿名安装 ID，无敏感字段 |

## 4. 需要胜算云后端确认的接口清单（阻塞 P1/P2）

| # | 接口 | 阶段 | 说明 |
|---|---|---|---|
| 1 | 充值页 URL + 是否支持 `from` 归因 | P0 | 产品确认即可 |
| 2 | `POST /auth/ticket` 一次性登录票据 | P1 | 或等价的免登录方案 |
| 3 | `GET /wallet/transactions`（流水） | P1 | 用于到账检测，二选一 |
| 3' | 支付成功 302 回 `ssyswitch://recharge-success` | P1 | 与 #3 二选一 |
| 4 | `POST /wallet/orders` + `GET /wallet/orders/{id}` + 二维码 | P2 | 原生充值 |
| 5 | 套餐/体验金/发票/退款规则的数据源 | P2 | 展示用 |

## 5. 安全红线

- URL、深链、日志、埋点中**永不**出现 api_key/jwt_token/完整卡号/订单敏感字段
- 客户端不签名、不校验金额、不碰资金流——一切以服务端返回为准
- ticket 一次性 + 短 TTL；深链回跳参数白名单校验（复用现有 oauth 深链模式）
- 自动刷余额保留现有节流（5 分钟缓存 + 手动刷新），防止轮询打爆 `/user/info`

## 6. 建议

先做 P0（零依赖、计划内工作、当天可上），同时把 §4 清单发给胜算云后端排期；
P1 是体验质变（免登录+自动到账），值得推动；P2 等充值转化数据证明有必要再投入。
